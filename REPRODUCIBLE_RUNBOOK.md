# Reproducible runbook — N0/R53 zero-input collapse study

This runbook describes how the tables and figures in the manuscript are produced from the
inputs, what can be regenerated from the files in this repository alone, and where
reproduction is expected to differ.

## 1. Environment

| Component | Version used |
|---|---|
| Python | 3.12.10 (local and compute host identical) |
| openseespy | 3.8.0.0 |
| numpy | 2.5.4 |
| scipy | 1.18.1 |

## 2. Inputs you must obtain

1. **Ground motions** — FEMA P695 far-field (44 components) and near-field (56
   components) horizontal records from the PEER NGA-West2 database
   (<https://ngawest2.berkeley.edu/>). Redistribution is not permitted, so the records are
   not in this repository; the record identifiers and scale factors used are in the
   derived outputs (`analysis/outputs/`) and in the archived `records.npz` produced by the
   campaign. Place them where `code/code_copy_R52/records.py` expects them.
2. **Archetype models** — the two-dimensional OpenSees models of Elkady & Lignos
   (<https://github.com/amaelkady/OpenSEES_Models_SMF>, GPL-3.0). The Tcl sources are not
   redistributed here.

## 3. Path configuration

All scripts were run in the author's archive layout:

- Windows: `E:\n0r53` (with `runs/`, `analysis/`, `code/`, `results/`)
- WSL: `/mnt/e/n0r53`

Two environment variables override the defaults where the code supports it:

```
N0R53_RUNS   # per-state output root, default E:\n0r53\runs
N0R52_RUNS   # R52-era runs reused for the IDA and t95 tasks
```

Other scripts carry the root as a module-level constant (`ROOT`, `RUNS`, `MS`, `A`). To
relocate the tree, edit those constants or create the same directory layout. No absolute
path contains anything but the drive letter; internal network shares have been replaced by
placeholders.

## 5. What can be checked from this repository alone

Every number quoted in the manuscript comes from `analysis/tables/numbers.tex`, which is
generated by `make_numbers53.py` from `analysis/outputs/*.json`. The derived outputs are
included, so the tables, figures and macros can be regenerated and checked without the
per-state output set — but *not* the campaign itself.

Rebuilding a figure from the derived outputs, e.g.:

```bash
cd analysis
python fig2_law.py      # writes figures/fig2_law.pdf
```

## 6. Known sources of non-reproducibility

- **Chaotic dynamics.** Halving the analysis step changes each individual realisation:
  individual escape energies move and individual boundary labels can flip. The energy
  coefficient is invariant when barrier and escape energy refer to the same realisation
  (manuscript, Methods and Supplementary Note 6).
- **Solver scatter on composite frames.** Repeated identical pushover runs deviated
  measurably on part of the composite-frame states and on none of the bare-frame repeats
  (addendum A13). Reported intervals resample events only and do not propagate this noise.
- **Server clock and scheduler order** do not enter any result; the campaign is
  deterministic given the same engine version and inputs.
- **Record scaling** follows the manuscript's `Sa(T1)` convention; a different convention
  changes intensities but not the classification result reported.

## 7. Provenance

Every per-state JSON in the campaign records its protocol tag and the SHA-256 of the code
that produced it. The frozen protocol (`protocol/PROTOCOL_R53.md`) lists addenda A1–A20
with the date and the scope of each post hoc decision.
